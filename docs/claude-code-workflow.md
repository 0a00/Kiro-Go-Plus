# Claude Code 文件任务规范

这是可选的客户端提示，不是服务端功能开关。Kiro-Go Plus 不会自动注入它，
也不会修改你的 `CLAUDE.md`、禁用 Bash 或重写工具调用。

## 使用方式

在 Bash 中，将路径改成当前仓库的绝对路径，从你的实际项目目录启动一个新会话：

```bash
WORKFLOW=/path/to/Kiro-Go-Plus/docs/claude-code-workflow-prompt.md
claude --permission-mode auto --effort max \
  --append-system-prompt "$(<"$WORKFLOW")"
```

该参数追加提示而非替换 Claude Code 的默认系统提示；沿用你现有的认证设置。
也可审阅模板后，按项目需要合并到已有 `CLAUDE.md`，不要覆盖原有规则。
使用 `--bare` 时不会自动发现 `CLAUDE.md`，显式追加的提示仍需自行传入。
已恢复的会话可能保留旧系统提示，验证规范时建议新建会话。

## 工具选择

- 普通文件修改优先 Read、Edit，新建文件可用 Write；部分客户端只提供 Edit。
- Bash 本身也是原生工具。测试、构建、格式化、合理的批量生成使用 Bash 是正常的，
  不能仅凭看到 `cat` 或 Python 就判断代理异常。
- 避免将整个大文件塞进一条 shell 命令；按功能分段修改并验证工具结果。
- 提示是偏好，不是强制策略，不能保证模型每次都遵循，也不能修复上游中断或权限问题。

## 如何验收

用功能和可执行检查描述目标，例如“增加参数校验、帮助信息及对应测试”，
不要只要求“增加五倍代码量”。模型说完成不等于完成，应检查磁盘结果、回读、
测试结果，以及是否仍有未恢复的工具错误。

专用大文件/分段压力测试现在同时验证：结构化调用和结果配对、正确目标文件、
工具参数重放与磁盘内容一致、420 行编号/长度、最终成功回读的内容覆盖。
这些是传输及文件完整性证据，不证明文本有用或真实应用功能正确。
测试会按场景限制工具；这不改变普通会话的工具权限。

离线回归无需密钥或生产环境：

```bash
node --test scripts/client-file-evidence.test.js scripts/client-e2e.test.js
```

真实模型测试会消耗额度，参见[开发测试说明](development-testing.md)。
此次仅修改文档和测试，无需调整服务器设置、重建容器或升级运行时版本。
